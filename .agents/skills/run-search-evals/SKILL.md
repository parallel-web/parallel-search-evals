# Run search evaluations

Read README, configuration and actual CLI help. Resolve model/provider/backend, DSQA or HLE, mode, local data identity and question count before paid calls. Reuse existing user choices and authorization; a request to inspect or draft commands does not authorize paid execution. Do not request confirmation again for an already authorized action.

Check credential presence without printing values. Use user-approved environments and never place keys in CLI arguments, reports or chat. Baseline still needs official grader credentials. No monetary spending cap is enforced; communicate that before a new paid evaluation.

Use one model/suite/mode per invocation and a fresh output directory when settings change. Keep questions, native settings and official grading identical across matched baseline/search runs. A configured model does not establish account access; start with a small authorized cohort. Do not substitute aliases or change backend/caps to force a result.

Only one writer may use a run directory. An identical rerun reuses valid terminal successes and failures; missing/malformed records rerun whole questions. There are no partial-answer checkpoints. Diagnose terminal failures rather than retrying them automatically. Inspect saved inspection/results artifacts rather than treating an SSH wrapper's zero exit as proof of success.

Report planned denominator, completed/failed counts, scores and exact settings. Unknown usage/cost is not zero. Run artifacts contain references and native responses and must remain private unless reviewed and sharing is permitted. Dataset rights and Security approval remain separate from a passing integration check. Posting or publishing requires authorization for that action.
